## Deviations from the plan (Tasks 1–15, 18)

Review subagents (Sonnet) read each substantive task; the controller (Opus) applied the smallest fix as a separate commit and kept everything else verbatim.

- **Fix commits after review:** `f747212` ledger, `d7f073f` gitutil, `09db297` runtime, `18088f4` core, `23c7668` verify, `221bbd1` eval baseline. Each adds tests; none changes a public signature or the ledger format.
- **verify has 9 checks, not 7:** "task folder is committed" and "base commit is an ancestor of HEAD" were added after the adversarial review of Task 12. Approver logins are compared casefolded, trimmed, with empty values dropped.
- **Identity:** `resolve_user` no longer falls back to `git user.name`. A display name never matches a GitHub reviewer login, so it would weaken the approver rule. Set `FACTORY_USER` or log in to `gh`.
- **Plan errors:** Task 9's test used `run_reviewer` before Task 11 (restored in Task 11). Task 15 cloned before committing the fixtures (reordered). Task 15 expected 7 ledger rows; the listed roles make 6. Task 18's anchor test depended on the live module and broke the demo task's test run.
- **Deferred, documented as limits:** no rollback if a ledger commit fails after the append; task-folder-only commits are not replayed against history; protected-path patterns are case-sensitive; the schema drift test is byte-exact against pydantic 2.14.3; the `--allowedTools` policy is not a hard sandbox (an agent can pass arbitrary arguments to pytest).
- **Provenance lesson from Task 16:** in the rehearsals the controller agent typed the plan approval under `FACTORY_USER=demo-user`, and the ledger records it as `human:demo-user`. Identity is self-asserted, so only the GitHub PR approval (checked in CI) is a strong human signal until entries are signed.
